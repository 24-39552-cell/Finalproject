## 5. Implement Student and Biometric Management

Connect student registration and management forms to the actual database.

The system must support student ID, name, grade level, section, school year, student status, and class assignment.

For facial registration:

1. An authorized Administrator or Teacher selects a student.
2. The camera is activated through the supported hardware workflow.
3. The system captures and validates the student's face.
4. The resulting biometric representation or reference is securely associated with the student.
5. The system records the registration result and displays accurate feedback.

For fingerprint registration:

1. An authorized user selects a student.
2. The system initiates the supported R307 fingerprint enrollment workflow.
3. The student places their finger on the sensor.
4. The sensor captures and enrolls the fingerprint template.
5. The system verifies successful enrollment and stores the appropriate reference or template ID.

Prevent duplicate student IDs and duplicate fingerprint enrollment where supported by the hardware.

Teachers must not register, update, or access biometric information for students outside their assigned classes.

Never display raw fingerprint templates or expose sensitive biometric data through ordinary API responses. Clearly distinguish biometric enrollment status from actual successful biometric verification.

## 6. Implement the IoT Attendance Workflow

Prepare the backend for integration with the ESP32, OV2640 camera module, and R307 fingerprint sensor.

The intended workflow is:

1. The device initializes the camera, fingerprint sensor, and network connection.
2. The device attempts facial recognition as the primary identification method.
3. If facial recognition fails or is unavailable, the student may proceed to fingerprint verification.
4. The system validates the identified student and checks their active enrollment and attendance eligibility.
5. The backend checks the applicable attendance period and existing records.
6. The system determines Present or Late based on configured attendance schedules and late thresholds.
7. If identification and validation succeed, the attendance transaction is saved to the centralized database.
8. The device provides the appropriate attendance confirmation.
9. The web dashboard displays the saved attendance record after successful synchronization.

If both identification methods fail, do not create an attendance record.

Record the verification method as either Facial Recognition or Fingerprint.

Associate each attendance transaction with its device and timestamp when available. Authenticate IoT devices and validate incoming requests to prevent unauthorized attendance submissions.

Do not assume that the OV2640 camera or ESP32 automatically supports full facial recognition. Implement the recognition process using a technically compatible processing architecture. If additional processing hardware or software is required, identify it clearly.

Do not simulate successful hardware operations. If the physical device is not yet available, implement and test the backend endpoints separately and clearly label hardware-dependent features as pending integration.
